# C54.5 — Viewport Scale Visual Hotfix

Signature: Tehkné Solutions

## Human visual review result

The C54 machine gate passed and produced a valid 1920×1080 PNG, but the capture failed human composition review:

- both fighters were pushed below the visible frame;
- the authored fighter was only partially visible at the bottom;
- the flipped fighter was clipped by the right and bottom edges;
- the canonical baseline and lower labels were outside the visible area;
- the cyan gameplay envelopes were scaled and displaced.

## Root cause

The bench authored its coordinates directly in a 1920×1080 space while the project root viewport used a smaller logical content space and stretched it to the 1920×1080 output. The existing capture-dimension check verified only the PNG dimensions, not whether the authored layout fit the logical viewport.

The observed displacement is consistent with the project content scale multiplying the authored coordinates before capture.

## Correction

The C54 bench now:

- declares a canonical authored canvas of 1920×1080;
- reads the active logical viewport size at runtime;
- derives a uniform layout scale from logical viewport to authored canvas;
- centers the authored canvas inside the active logical viewport;
- preserves the 132 px final visual target after project stretch;
- validates a safe-frame contract before capture;
- emits viewport, authored-canvas, layout-scale and safe-frame markers;
- extends the gate so a 1920×1080 file alone is no longer enough for PASS.

The BASE-00 art master, SHA-256, alpha bounds, pivot and baseline contract remain unchanged. Human visual review remains required after rerunning the bench.
